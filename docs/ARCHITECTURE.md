# 架构与状态机

本文面向维护者，说明小鲁班桌面宠物的运行时边界、状态所有权和关键不变量。具体操作见[用户指南](USER_GUIDE.md)，素材生成见[动画与图集管线](ANIMATION_PIPELINE.md)，命令和验收边界见[测试与发布](TESTING_AND_RELEASE.md)。

## 1. 设计目标

- 离线运行，不依赖账号、网络接口或后台服务。
- 一个 UI 线程统一提交人物帧、窗口位置和缩放，避免多个时钟争抢视觉状态。
- 支持 Windows 11、Per-Monitor V2 DPI、多屏和负坐标副屏。
- 动画画质优先；内存通过分页、LRU 和缓冲池控制，不靠降低源图分辨率换取占用下降。
- 待办、定时任务和设置分别持久化；定时任务加载失败时进入禁止覆盖保护。

## 2. 进程与窗口

```text
App
 ├─ 当前会话单实例 Mutex
 ├─ MainWindow：透明桌宠包络、动画与全局调度
 │   ├─ BubblePopup：人物对白
 │   ├─ TodoWindow：待办、定时任务和设置面板
 │   └─ ReminderWindow：最多每页 5 条的到点提醒
 └─ TrayIconService：通知区域图标和退出入口
```

`MainWindow` 使用固定 `454×454 DIP` 透明包络，人物基准显示区域为 `190×242 DIP`。固定包络避免右键、收起、缩放或换动作时反复改变原生 HWND 尺寸；人物的真实可见边界必须由当前精灵帧、枕头层和用户缩放共同计算，不能把整个透明包络当作接触边界。

`TodoWindow`、`ReminderWindow` 和编辑窗口都是主桌宠拥有的 WPF 窗口。它们的位置通过 `OwnedWindowPositioner` 以物理像素对齐，不能用单屏假设或只按主显示器坐标计算。

## 3. 状态所有权与优先级

`MainWindow` 是人物视觉的唯一所有者。下列状态可能请求人物帧或窗口移动，冲突时按交互优先级收敛：

1. 应用关闭与系统恢复。
2. 定时提醒。
3. 用户拖动和桌宠大小调整。
4. 任务面板打开、收起及对白。
5. 手动左、右、下边缘探头。
6. 用户主动进入的打工状态。
7. 熊猫坐骑巡游。
8. 点击动作和自动待机动作。
9. 枕头呼吸与单个半透明呼噜泡泡。

高优先级状态接管时，必须先让低优先级状态停止写入。尤其不能让巡游位置更新和捕获式物理拖动同时修改窗口位置，也不能在 `CompositionTarget.Rendering` 回调中直接打开 owned window。

### 3.1 对白状态

`BubbleMode` 区分无对白、待办过渡和提醒等视觉语义。任务面板只在人物完成对应入场或退出交接后取得焦点；关闭提醒不得破坏仍在编辑的待办或定时任务窗口。

### 3.2 手动边缘状态

`EdgeDock` 只有 `None`、`Left`、`Right` 和 `Bottom`。顶部是普通可拖动区域：人物可见内容可以贴到当前显示器工作区顶沿，但不会产生 `EdgeDock.Top`，也不会播放顶部探头。左上角和右上角同时触及侧边时，仍分别按左、右边缘处理。

左、右、下边缘探头仍拥有人物视觉，但会保留可命中的“去打工”入口。点击后不能让边缘帧和打工帧同时写入：先以 60 fps 作者序列播放到稳定缩回端点，清除 `EdgeDock`，再调用严格的待机打工入口。右边缘继续镜像人物，按钮文字通过子级反向缩放保持正向。

### 3.3 熊猫巡游状态

巡游使用 `Boarding → Traveling → Disembarking` 三阶段：

- 空闲期限到达后先播放登乘，再沿当前显示器工作区边界移动。
- 左键单击会在当前位置停止移动、反向播放下坐骑并回到稳定待机，不再追加七种点击动作。
- 用户开始拖动时，巡游立即释放位置所有权，再交给捕获式物理拖动。
- 右键会先在当前位置平滑下坐骑，再通过一次 Dispatcher 调度打开默认待办页。
- 提醒、关闭程序或关闭绕屏开关会取消尚未执行的“巡游结束后打开待办”请求。

巡游退出必须冻结最后一次已呈现的支撑点；不能回跳到本轮路线起点后再播放下坐骑。

### 3.4 打工状态

打工是用户主动进入的常驻状态，不属于七种普通点击动作，也不写入设置文件。主状态与打字子阶段的交接为：

```text
Idle → WorkEntering → NormalTyping
EdgeDock → authored retreat → Idle → WorkEntering
NormalTyping → HeadTap → NormalTyping
NormalTyping → 2x-to-exact-seam → SeriousBrowTransition → SeriousTyping → SeriousExit → NormalTyping
NormalTyping / SeriousTyping → WorkExiting → Idle
```

- 胶囊按钮在完全待机和左/右/下边缘吸附时显示“去打工”，进入任一非待机打工状态后单源切换为“下班啦”；按钮事件不能冒泡成普通人物点击。
- 普通 `work-loop` 使用 96 个逻辑帧形成 1.6 秒完整循环；其中 81 张位图独特，一圈包含 8 个精确中性接缝，最长连续相同画面只有 3 帧。6 次强触键之间穿插 2 次轻微换位，同手连击和左右交错共同打破机械轮播。
- v6 打字姿势把每侧肩、上臂、肘、袖口、手腕、掌根和四指作为一条完整关节链，位移从近端到指尖逐级增大；目标指尖实测位移为 `5.814–7.055 px`。专用眉形补丁之外的脸、电脑以及双臂允许区域外属于静态锁区，逐像素漂移必须为 `0`。
- 第一次简单单击必须等待 Windows 系统双击时间。确认为单击后只播放 48 帧 `work-tap` 敲头反应，其末端回到普通循环的精确中性接缝并继续 1 倍速，不进入认真状态。
- 若系统双击窗口内收到第二次单击，则取消待执行敲头，立即把当前普通循环连续切到 2 倍速；到最近的精确中性接缝后播放约 `133 ms` 的认真眉过渡，再进入 96 帧 `work-serious-loop`，从认真循环开始时完整计时至少 4 秒。已在认真循环时再双击会从当前时刻重新建立完整 4 秒期限，不重置手部相位。
- 认真期限到期后等待最近的精确中性接缝，进入 24 帧 `work-serious-exit`，再以 1 倍速恢复普通打字；不得在任意触键相位硬切。
- 打工期间禁止自动动作、呼噜和绕屏启动。提醒、真实拖动、右键打开任务面板、会话锁定和退出拥有更高优先级，并取消所有待执行单击。
- 右键从打工状态打开任务面板时，先完成收工交接，再通过 Dispatcher 调用原有面板入口，不能在渲染回调中直接打开窗口。

## 4. 动画与渲染

人物动作、边缘探头和熊猫巡游共享 `CompositionTarget.Rendering + Stopwatch` 绝对时间轴。渲染回调只做内存中的帧选择、像素提交和变换更新：

```text
Stopwatch 绝对时间
       ↓
动作/巡游/边缘状态计算
       ↓
定位当前逻辑帧与高精度坐标
       ↓
复用像素缓冲并提交 WriteableBitmap
       ↓
Left/Top 最后对齐物理像素
```

- 掉帧后直接定位到当前绝对时间对应姿势，不补播积压帧。
- 超过 `250 ms` 的休眠或 UI 阻塞不补移动距离，恢复后不得瞬移。
- 相邻姿势直接切换；只有明确设计的状态桥接才允许过渡，不能用整图交叉淡化制造双影、光纹或忽大忽小。
- `Rendering` 只在动画、移动或过渡活动时订阅；稳定待机不应维持空转回调。
- 回调内禁止磁盘 I/O、页面解压和大对象逐帧分配。

动作全局倍速由 `MainWindow.xaml.cs` 的 `AnimationPlaybackSpeed` 代码常量控制，不提供持久化速度滑块。桌宠大小是用户设置，范围为 `75%～140%`。

## 5. 图集与内存

正式精灵位于嵌入式 Brotli Pbgra32 分页图集中。程序启动只同步解码待机所需页，其他页面按动作预取：

- `v1.0.54` 的打工资源契约为 312 个逻辑帧：`work-enter`、`work-loop`、`work-tap`、`work-serious-loop`、`work-serious-exit` 分别为 48、96、48、96、24 帧；两种循环均保留 8 个精确中性接缝和 81 张独特位图。这些动作长度仍由清单动态读取。
- `v1.0.52` 的历史清单快照为 53 页、1600 个源帧和 1600 个分页帧，当时五段打工序列分别为 48、48、48、48、24 帧。整个图集的当前总帧数和分页数必须读取 `Assets/luban-sprite-pages.json`，不能从历史快照推断。

- 常规 resident 预算：`64 MiB`。
- 熊猫巡游期间预算：`104 MiB`。
- 稳定空闲收敛目标：`24 MiB`；保留完整待机页与第一张起身续页，不保留无关空闲桶。
- 左、右、下边缘探头仅在静止保持段允许空闲收缩；运动段仍禁止回收，并保护完整边缘序列页。
- 单页解码上限：`24 MiB`；像素缓冲池总上限：`104 MiB`。

启动后台解码前会先归还稍后必然淘汰的非保护 LRU 页，使同桶或仅大 `1 MiB` 的最近容量桶可直接复用；当前、pending、desired、固定待机和巡游保护页不能预淘汰。LRU 淘汰、预取取消和退出都必须归还像素数组，迟到结果不能在状态结束或应用关闭后重新常驻。普通 Gen2 不代表 LOH 已压缩，分页淘汰债务只能在程序显式请求的空闲压缩完成后扣除。清单帧数、分页数和动作长度均从 `Assets/luban-sprite-pages.json` 动态读取，不得把文档快照当作运行时契约。

## 6. 多屏、DPI 与窗口几何

`MonitorWorkArea` 负责选择人物当前所在显示器的工作区，`OwnedWindowPositioner` 负责 WPF DIP 与物理像素之间的定位。位置计算遵循以下规则：

- 内部使用高精度逻辑坐标累计；只在最终写入 `Left/Top` 时对齐物理像素。
- 每次跨屏或 DPI 变化后重新取得当前显示器工作区，不能复用主屏比例。
- 拖动接触判定使用当前帧可见像素，而不是固定透明包络。
- 按住鼠标期间以光标物理坐标选择显示器，并用 `GetWindowRect + SetWindowPos` 直接移动 HWND；固定透明包络可以越过工作区顶边，当前帧可见顶边不得越过 `rcWork.Top`。
- 顶部夹紧后重新锚定抓取点，向下一个物理像素就应立即离开；该限制只约束普通位置，不创建顶部吸附状态。
- 共享显示器接缝不是外部屏幕边界，不应误触发侧边吸附。

## 7. 数据与定时任务

```text
TodoWindow / 编辑窗口
      ├─ TodoStore ─────────────── todos.json
      ├─ ScheduledTaskStore ────── scheduled-tasks.json
      ├─ AppSettingsStore ──────── settings.json
      └─ StartupRegistration ───── HKCU ...\Run
```

JSON 文件采用临时文件替换，避免正常保存过程中留下半写文件。循环定时任务保存下一次触发时间、重复规则和每日免打扰时间段；重启后根据持久化状态继续计算。错过的批次进入漏提醒统计，但提醒窗口每页最多加载 5 条，避免无限叠高。

开机自启属于当前用户注册表状态，不写入 `settings.json`。程序移动后，已启用的启动路径由后续正常启动检查和修正。

## 9. 修改检查清单

- 新状态是否有明确的视觉和位置所有权？
- 高优先级交互是否取消了旧回调、定时器和延迟请求？
- 是否仍由一个绝对时钟定位帧，而不是逐帧累加误差？
- 是否保持固定透明包络、高清源图和物理像素对齐？
- 是否覆盖 75%、100%、125%、140% 桌宠大小以及多屏/DPI？
- 是否保持待办、定时任务、设置和开机自启的持久化边界？
- 是否同步更新用户指南、测试发布说明和变更记录，并准确标注未验证项？
