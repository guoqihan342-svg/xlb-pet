# 小鲁班桌面宠物

一个面向 Windows 11 的轻量桌面宠物，使用 WPF 和 .NET 8 构建。启动后，小鲁班会趴在枕头上打呼噜，鼻尖的泡泡会慢慢变大再缩回，安静待在屏幕右下角、任务栏上方。

## 功能与操作

### 人物动作

- 左键单击小鲁班会依次触发 7 组独立动作：打哈欠、委屈、欢呼卖萌、点赞、吃饼干、挥手和托腮思考；第 8 次有效点击重新从打哈欠开始。原有跑步动作已经完整移除，不会出现在点击或随机动作中。
- 每组点击动作都会经过“趴枕头待机 → 连续起身 → 专属动作 → 原路返回待机”。姿势以 60fps 目标节拍播放，起身、动作入口和变化较大的动作内部使用经过连续性检查的补间姿势；实际帧数由最终资源序列和图集清单动态决定。挥手只使用没有多手重影的前 40 帧；“欢呼卖萌”把原先第二次上下弹跳的帧预算重新分配给第一次蹲起，在前 56 帧完成一次连续下蹲、回弹和张嘴笑，不再重复抖身高。“嗨~我在这里！”和“给你卖个萌”会在完整末姿势停留约 1.5 秒后返回，比原版本实际多停留 1 秒，其余五组继续使用完整循环段。
- 动画播放期间再次点击不会重启动作或追加队列；拖动也不会误触点击动作。
- 没有操作时，每隔约 1 分钟，小鲁班会从 7 组动作和趴枕头打呼噜待机中随机选择一种，不按固定顺序机械重复。

### 手动屏幕边缘探头

- 左键拖动可以移动小鲁班。人物可见边缘进入当前显示器工作区左、右或下边界的 `12 DIP` 磁吸区，或快速拖动稍微越过外边缘后松手，都会可靠吸附并进入探头状态；超过磁吸区时不会提前触发。从右侧吸附沿边快速向下甩到底部时，会按向下手势切换到底边，即使松手很快也不会被旧的右侧状态抢回。顶部中央不吸附、不播放边缘动作；拖到左上角或右上角时仍分别按左、右边缘处理。
- 左、右、下三个方向保留对应姿势。小鲁班会按“藏起来 → 悄悄偷看 → 开心地完全探头 → 害羞缩回”的节奏，交替抓紧边缘、歪头、眨眼并露出一点肩膀；开心探头会停留 650ms，缩回后的休息时间自动补足，使每一轮严格为 10 秒。背景透明，不绘制黑墙或黑色挡板。
- 探头只在手动拖到边缘并松手后触发；再次把小鲁班拖离边缘后，会恢复普通待机和随机可爱动作。
- 待办事项打开时也可以直接拖到边缘；随后点击其他地方只会保存并收起待办窗口，已经进入的边缘探头状态和动画会继续保留。
- 支持双屏和多屏：按人物当前所在显示器读取独立工作区，支持副屏负坐标、不同 DPI/缩放率，并避开各屏任务栏。显示器热插拔或分辨率变化后，会重新校准人物位置和边缘吸附状态。

### 自动熊猫坐骑巡游

- 可爱的绕屏动画默认开启。小鲁班空闲约 10 分钟且没有待办、提醒、拖拽或其他人物动作时，会登上戴铃铛、背竹筒的大头熊猫坐骑，沿当前显示器工作区内侧的圆角矩形完整巡游。不使用已经删除的跑步，也不换成爬行或蠕动姿势。
- 熊猫坐骑横向移动时始终朝前；往上或往下经过左右竖边时，人物与坐骑整体按方向旋转 90°，不会仍横着平移。顺时针和逆时针路线都会在第一帧使用正确方向，不先反向闪一下再翻转。
- 坐骑上的小鲁班恢复原版大眼造型：暖棕色分层虹膜、白色眼缘和稳定的主副高光。闭眼关键姿势保持原样，开眼、眨眼和重新睁眼由密集帧连续衔接；眼部只修改 RGB，熊猫、人物轮廓、透明 Alpha、尺寸和位置均不改变。
- 自动路线可以平滑经过工作区顶部，但它是独立的熊猫坐骑巡游段，不会恢复手动顶部吸附。把人物拖到顶部中央松手仍不探头，手动边缘状态继续只支持左、右、下。
- 右键窗口在“桌宠大小”上方提供“绕屏动画”勾选项，默认勾选。取消勾选会先倒放登乘序列，让小鲁班平稳离开熊猫坐骑，再恢复稳定待机；重新勾选只安排下一次空闲巡游，不会关闭其他七种随机可爱动作。选择会保存到 `%LocalAppData%\LubanDesktopPet\settings.json`，下次启动继续沿用。
- 每次出发只使用人物当时所在显示器的独立 `WorkArea`，不会从双屏共享边界突然跳到另一块屏幕，也不会盖住任务栏。负坐标副屏、100%/125%/150% DPI、不同缩放率和显示器热插拔都会重新计算路线；用户把人物拖到另一块屏幕后，下一次巡游使用新屏幕。
- 左键点击或拖动会立即结束巡游并回到趴枕头待机；右键打开任务窗口、手动边缘探头、尺寸调节和定时提醒也会优先抢占巡游。停止后不补播积压位置或姿势，也不会让旋转后的熊猫坐骑画面翻转或一闪而过。

### 待办事项

- 右键单击小鲁班可打开或收起备忘窗口。窗口顶部提供“待办事项 / 定时任务”两个胶囊选项卡，每次打开默认显示待办事项。待办支持新增、回车添加、勾选完成、删除、修改文字和拖拽排序，内容与当前顺序都会自动保存到 `%LocalAppData%\LubanDesktopPet\todos.json`。输入框和行内编辑都支持 `Ctrl+X`；即使剪贴板被其他程序短暂占用，也会保留原文字和选区，复制成功后才执行剪切。
- 每行左侧的 `≡` 是专用拖拽手柄；从手柄拖动即可调整顺序，不会抢占正文的鼠标选择和 `Ctrl+C`。每条待办最多输入 5000 字。只有正文确实被当前行裁掉时，鼠标悬停才会在左侧显示“待办完整内容 · 可选择复制”；左侧空间不足才改到右侧，短内容不弹窗。行内只允许选择当前看得到的文字，拖到行外不会偷偷向下滚动。单击每行右侧笔尖朝左下的铅笔图标，会打开固定约 `10cm × 5.5cm` 的浅蓝萌系编辑窗，优先放在面板左侧、空间不足时放到右侧；鼠标点到编辑窗外自动保存，按钮显示“确定修改”，`Ctrl+Enter` 保存、`Esc` 取消。`F2` 仍可进入兼容的行内修改。空白内容不会覆盖原待办，微软输入法仍在选词时会等候文字正式上屏再保存。
- 待办使用独立的 WPF `Owned Window`，而不是嵌在 `Popup` 中。这解决了微软拼音候选框跑到屏幕左上角的问题，也能正确保护输入法选词期间的 Enter 键。
- 拖动小鲁班时，待办窗口会跨屏、跨 DPI 跟随人物并保持展开；单击小鲁班（非拖动）、桌面或其他应用会自动收起。
- 待办与定时任务列表均按物理像素连续滚动并复用可视行，滚轮和拖动橘色圆角滑块时不会逐项卡跳；更多内容只在列表内部滚动，不会继续撑大窗口。
- 待办窗口提供“收起”“退出”、默认勾选的“绕屏动画”、默认关闭的“开机自启”和桌宠大小滑块。开机自启只使用当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，不需要管理员权限，也不写入 `settings.json`；每次启用、停用和旧路径修复都会立即读回校验，失败则恢复原值。移动 EXE 后手动运行一次会修复已启用的旧路径。绕屏勾选直接位于尺寸滑块上方，只控制自动熊猫坐骑巡游。默认逻辑尺寸为 `190×242`，可在 75%～140% 之间连续调节。缩放预览由屏幕合成时钟平滑驱动，停止调节后才一次性保存到 `%LocalAppData%\LubanDesktopPet\settings.json`，避免频繁重排窗口和写磁盘。所有姿势共用同一尺寸基准，打开或收起待办不会让人物忽大忽小。
- 启动后，Windows 右下角通知区域会显示小鲁班头像图标；右键图标选择“退出小鲁班”会走正常关闭流程，先保存待办、定时任务和设置，再立即移除托盘图标，不留下僵尸图标或第二个进程。
- 桌宠、待办窗口、提示文字和控件统一使用微软雅黑，避免不同窗口回退到不同系统字体。

### 定时任务

- 在右键窗口切换到“定时任务”，新草稿默认是单次提醒并带入当前本地日期与整秒。点击日期框会打开固定六周的暖橙色圆角月历，支持上月、下月、跨年、闰年、今天快捷选择与相邻月份日期；点击时间框则用时、分、秒三列选择器调整，完整显示 `HH:mm:ss`。逐列选择时只收起当前列的下拉列表；勾选循环、修改次数或切换循环单位也不会收起外层“选择提醒时间”窗口，只有点击“确定”、按 `Esc` 或明确点击外部才会关闭。
- 循环方式使用“每 N 分钟 / 小时 / 天”的直观规则：每 N 分钟固定所选秒数，每 N 小时固定所选分秒，每 N 天固定所选时分秒。例如 `每 1 小时，第 11 分 10 秒`、`每 3 小时，第 11 分 10 秒`、`每 1 天，11:11:11` 都会按本地时区和原始节奏推进。规则、下一次时间和循环序号都会持久化，电脑重启或离线错过多次后不会从保存时刻重新计时。
- 待办和定时任务正文均最多输入 5000 字，全文悬停规则与待办一致。单击定时任务右侧铅笔会打开固定约 `10cm × 5.5cm` 的橘色独立编辑窗，优先放在面板左侧、空间不足时回退右侧；正文、日期、时、分、秒和循环规则一次回填、一起修改。修改窗与新增表单使用同款 `yyyy-MM-dd` 暖橙月历和 `HH:mm:ss` 三列时间组件；依次选择时、分、秒，或勾选循环、修改次数、切换循环单位时，外层选择时间窗都会保持，`Esc` 先收起选择窗而不取消整个修改。内容较多时只在窗内平滑滚动。“确定修改”或点击窗外只提交一次并保留任务身份，然后重新排序和调度；没有打开内部选择窗时按 `Esc` 才取消且不会误改原任务。待提醒列表自动保存到 `%LocalAppData%\LubanDesktopPet\scheduled-tasks.json`。
- 到点时，小鲁班会中断普通动作、平滑放大到 140%，换成闭眼笑着双手举喇叭的专用姿势，先轻轻回正，再进行左右小幅播报摇摆，并在独立的黄白色可爱提醒窗中显示完整内容；人物、双手、喇叭和声效线始终是同一个完整高清轮廓，不再使用会悬空、穿模或产生光纹的矢量贴层。若右键任务面板正在打开或编辑，面板、当前选项卡、输入内容和焦点状态都保持不变，提醒窗只显示在旁边。提醒尚未确认时又有新的发生项到点，消息只追加一次，小鲁班会重新摇一次喇叭提醒，不重建窗口或清空旧内容。长内容可滚动、选中和复制。点击“知道啦”后才算完成，并平滑恢复提醒前的桌宠大小，不会把临时 140% 写进用户设置。
- 已到点的每一次任务按“到期时间 → 创建时间 → 标识”从上到下排列；循环任务在用户尚未点击确认时，每次再次到点都会继续追加，而不是覆盖上一条。提醒窗一次明确列出最早的 100 条；内容更多时窗口会向屏幕上下方向扩展到当前工作区高度，并标出剩余数量。确认只处理当前显示的最多 100 条，余下内容立即继续显示，绝不会跳过。
- 到点不会立刻从磁盘删除任务，只有用户点击“知道啦/都知道啦”后才原子保存结果。单次任务会删除；循环任务只按本次已经确认的发生次数沿原始节奏推进。提醒期间退出或崩溃时，尚未确认的每次发生记录都能根据持久化节奏在下次启动恢复，不会静默丢失或把下一次时间错误跳到很远的未来。
- 如果启动时定时任务文件暂时被占用、无权读取或 JSON 损坏，本次运行会进入只读保护，不会在退出时把原文件覆盖成空列表。

项目不需要联网、账号或后台服务。

## 动画与内存

- `pic` 文件夹中的 9 张原图全部保留：`小鲁班2.png` 用作趴枕头打呼噜待机，7 张对应现有点击动作；`小鲁班4.png` 仅作为原始参考图保留，跑步动作移除后不再参与运行时动画和图集。
- 最终起身、动作、循环和熊猫坐骑巡游序列采用可变长度编号帧。`Assets\luban-roam-boarding-001.png` 起的登乘序列与 `Assets\luban-roam-flight-001.png` 起的连续主循环都至少 48 帧且每帧姿势不同：开始巡游正放 boarding，停止巡游倒放同一序列，随后才回到待机。熊猫坐骑上的小鲁班使用统一宽高、虹膜和高光比例的成对大眼创作源；构建器会检查 16 个开眼关键姿势与最终 64 帧主循环，只要一只眼被单独放大或缩小就直接停止构建，闭眼区间单独排除。熊猫眼睛、熊猫轮廓和透明通道不参与这项修饰。`roam-wave` 只是可选的可爱补充，可以不加载或不播放，不能按固定 7 秒硬切打断 flight 主循环。构建器按磁盘资源动态分配 `roam-boarding`、`roam-flight` 及可选 `roam-wave` 分页；最终逻辑帧数、页内帧数和分页数以 `Assets\luban-sprite-pages.json` 的 `sourceFrameCount`、`pageFrameCount` 和 `pages` 为准，不在代码或文档中写死最终图集总数。
- 精灵以 `399×509` 高密度像素渲染，对应 `190×242` 逻辑显示基准。即使 Windows 使用 150% DPI 且桌宠大小调到 140%，仍有足够的源像素，不需要把低清小图放大；所有姿势使用统一逻辑边界和基线，避免动画中的缩放抖动。
- 枕头使用独立的静态透明层，人物待机和起身帧只更新人物本身。鼻尖只显示一个半透明高质量矢量泡泡；运行时先用局部无泡泡补片遮住旧素材中的烘焙泡泡，再让这一个矢量泡泡以鼻孔为锚点平滑呼吸。补片不会替换眼睛、帽子或整张人物素材，泡泡也不会缩放整个人物、改变布局或重新引入 Alpha 光纹和忽大忽小。
- 图集清单使用 `version: 4`、`compression: "brotli"` 契约。运行时资源是无损 Brotli 压缩的 Pbgra32 分页（`*.pbgra.br`）；默认构建不保存约 `115.6 MiB` 的派生分页预览 PNG，每一页解码后不超过清单声明的 24 MiB 上限。
- 启动时只同步解码首个待机页，不再常驻预热提醒、左/下探头、熊猫坐骑巡游或后续起身页；右侧镜像复用左侧分页，手动顶部分页仍不进入运行时图集。动作、`roam-boarding` 和 `roam-flight` 的分页会在播放前后台载入，可选 `roam-wave` 只在实际使用时加载。为了避免巡游中途因冷页停顿，活动期间会保护 boarding 与 flight 所需分页，结束后立即重新进入普通 LRU 回收。定时提醒首分页在到期前 `2 秒`预取。活动期 resident LRU 软预算为 `128 MiB`，普通待机后裁到 `104 MiB`，能同时保留完整待机/起身和常用动作页，避免反复解压造成卡顿。解码页通过 `160 MiB` 上限的精确长度缓冲池复用，取消、过期预取、重复页、LRU 淘汰和退出路径都会归还；只有池真正释放大数组后，才可能在完全空闲窗口低频请求非压缩 Gen2。像素尺寸、帧数、预乘 Alpha 和哈希校验均不改变。
- 人物动作、鼻尖呼噜泡泡、自动熊猫坐骑巡游和手动边缘探头共用单一 `CompositionTarget.Rendering + Stopwatch` 绝对时间轴。泡泡使用 2.4 秒余弦周期，周期端点速度自然归零；巡游的窗口位置按显示器刷新率连续更新，登乘和退场按绝对时间在 `roam-boarding` 中正向或反向定位，移动阶段则持续循环可变长度 `roam-flight`；逻辑坐标保持高精度，只在写入 `Left/Top` 时对齐物理像素。超过 250ms 的休眠或界面阻塞不会补移动距离，也不会快速补播积压姿势。边缘探头继续使用 `48` 帧闭环、原生 60fps 姿势节拍，在序列前半完成“藏起来 → 偷看 → 开心探头”并停留 650ms，再连续害羞缩回；末帧休息时长按剩余周期动态计算，使完整循环严格为 10 秒。相邻姿势直接发布清晰单帧，较大变化由专用桥接姿势连接，不做整图交叉淡化。
- 边缘探头补帧先在画布内保留完整的头、肩膀和双手轮廓，最后才按连续位移裁到 Windows 边界；不能把已经裁断的手交给补帧器。这样双手在接触线附近不会突然出现、消失，也不会用整图淡化产生双层轮廓、光纹或缩放抖动。构建前会把完整关键姿势按端点偏移重新裁切，并与左、下共 8 张运行时关键帧逐像素比对，源图不一致时在启动耗时补帧前立即失败；顶部 4 张关键姿势只作为未嵌入的创作源保留。
- 定时提醒素材库保留 8 张核心姿势和 8 张桥接候选，运行时选用其中闭眼举喇叭的完整姿势生成 33 帧阻尼回正和 48 帧轻柔播报摇摆；收起过程反向复用入场帧，不保存第二套退场 PNG。生成时始终对人物、双手、喇叭和声效线这一整块预乘 Alpha 轮廓做确定性刚体变换，不在不同人物姿势之间做光流变形或整图淡化，因此不会生成双手、双喇叭、光纹和忽大忽小的插值中间态。
- 点击动作和自动原地动作的播放速度通过 `MainWindow.xaml.cs` 顶部的代码常量 `AnimationPlaybackSpeed` 配置，默认值为 `1.25`；熊猫坐骑的移动速度使用独立代码常量，二者都不提供速度滑块，也不会持久化，修改后需要重新编译程序。“绕屏动画”勾选只保存启用状态，不会改变七种原地动作、手动边缘探头、自动待机间隔或桌宠大小缩放动画。
- 渲染过程复用一个可见 `399×509 Pbgra32` 位图和工作缓冲，只提交新旧人物边界的脏矩形。Brotli 分页会直接流式写入最终图集缓冲，delta-sub 也逐头、逐行重建，不再为最大分页永久保留约 `22 MiB` 的压缩和 payload 工作区；所有淡化时长为零时也不会分配三张未使用的整帧缓冲。渲染回调不读盘、不解压、不写文件，也不会为每一帧创建新位图。

## 重新发布

以下命令生成依赖 .NET 8 Desktop Runtime 的 Windows x64 单文件版本：

```powershell
dotnet publish .\DesktopPet.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -p:DebugType=None -o .\dist
```

发布结果位于 `dist\LubanDesktopPet.exe`。这是依赖 .NET 8 Desktop Runtime 的框架依赖单文件程序，不是自包含运行时包。

发布前必须先确认最终清单已经是 Brotli v4，并检查 EXE 大小和哈希：

```powershell
$manifest = Get-Content .\Assets\luban-sprite-pages.json -Raw | ConvertFrom-Json
if ($manifest.version -ne 4 -or $manifest.compression -ne 'brotli') {
    throw '最终图集不是Brotli v4，禁止发布'
}

$exe = Get-Item .\dist\LubanDesktopPet.exe
if ($exe.Length -ge 100000000) {
    Write-Warning 'EXE达到GitHub普通Git对象100,000,000字节硬限制；请上传GitHub Release附件，不要提交到Git历史'
}
if ($exe.Length -ge 95000000) {
    Write-Warning 'EXE已接近100,000,000字节硬限制；发布前应减少边缘序列或改用Release附件'
}
if ($exe.Length -ge 50MB) {
    Write-Warning 'GitHub会对超过50 MiB的普通Git对象给出大文件警告'
}

$exe | Select-Object FullName, Length, LastWriteTime
Get-FileHash $exe.FullName -Algorithm SHA256
Get-AuthenticodeSignature $exe.FullName | Select-Object Status, StatusMessage
```

当前程序没有商业代码签名，因此签名状态预计为 `NotSigned`；这不是哈希失败。最终发布还需要实际启动 EXE，逐项冒烟检查点击动作、默认开启和取消熊猫坐骑巡游、快速拖动大小、待办输入与复制、窗口外点击收起、左/右/下手动探头、顶部中央不吸附、双屏/DPI、提醒堆叠、托盘退出，并确认运行前后都没有创建 `log` 文件夹。
